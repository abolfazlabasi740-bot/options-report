# قرارداد اجباری «بحث آموزشی» در هر گزارش

## هدف

هر گزارش باید علاوه بر رتبه‌بندی، یک بحث آموزشی قابل ممیزی داشته باشد. این بحث برای کشف خطا، آزمون فرضیه و بهبود جمع‌آوری داده است؛ «سیگنال معاملاتی» و «تغییر خودکار مدل» نیست.

## حداقل خروجی

بخش آموزشی هر گزارش باید شامل این موارد باشد:

| فیلد | الزام |
|---|---|
| Claim | ادعا یا درسی که از این اجرا به‌دست آمده است |
| Evidence | شناسه Run، فایل، منبع و زمان تصمیم |
| Confidence | HIGH/MEDIUM/LOW با دلیل |
| Disconfirming evidence | چه داده‌ای می‌تواند این ادعا را رد کند |
| Action | اقدام بعدی قابل اجرا |
| KnowledgePromotion | وضعیت ارتقا به دانش معتبر |
| AutomaticModelChange | همیشه `false` مگر با فرایند تأیید مستقل |

## قواعد ضد خودفریبی

1. `Last-to-Last` فقط بازده فرضی است؛ بدون bid/ask، کارمزد، اسلیپیج، حجم و وضعیت خروج، موفقیت معاملاتی نیست.
2. Missing با صفر، مقدار خنثی یا امتیاز ساختگی جایگزین نمی‌شود.
3. جهش با حجم یک، spread بزرگ، quote نامعتبر یا قیمت stale باید به‌عنوان outlier/غیرقابل‌اجرا پرچم بخورد.
4. هر نتیجه باید با زمان رویداد و اطلاعات قابل دسترس در زمان تصمیم ساخته شود؛ داده منتشرشده بعد از تصمیم ممنوع است.
5. گزارش آموزشی حق تغییر خودکار وزن، Rule، آستانه یا پروتکل Production را ندارد.
6. «رتبه‌بندی کیفیت» با «پیش‌بینی بازده» یکی نیست؛ این دو باید جدا گزارش شوند.

## نقش اتاق فکر

برای هر ادعا، نقش‌های زیر باید در صورت وجود داده اظهار نظر کنند:

- Quant: تعریف label و آزمون walk-forward
- Microstructure: bid/ask، spread، عمق و قابلیت اجرا
- Fundamental: کیفیت سود، دوره مالی و تازگی کدال
- Risk: tail risk، سررسید و زیان نامتقارن
- Data/Governance: lineage، hash و drift
- Skeptic: مثال نقض و فرضیه جایگزین

اگر داده یک نقش موجود نباشد، گزارش باید صریحاً `NOT_AVAILABLE` بنویسد، نه اینکه سکوت کند.

## ارتقای دانش

ثبت آموزشی هر اجرا در `library/reports` و `library/raw_experience` انجام می‌شود. ورود به `library/validated_knowledge` فقط پس از داشتن منبع اجرا، تعداد نمونه، رژیم بازار، اندازه اثر، فاصله اطمینان، هزینه معامله، و امکان بازتولید مجاز است.
